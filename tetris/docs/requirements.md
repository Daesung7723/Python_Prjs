# 테트리스 게임 - 요구사항 분석서

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|
| 프로젝트명 | Python Tetris |
| 개발 언어 | Python 3.10+ |
| 목적 | 키보드 방향키와 스페이스바로 조작하는 클래식 테트리스 게임 구현 |

---

## 2. 기능 요구사항 (Functional Requirements)

### 2.1 게임 보드

| ID | 요구사항 |
|----|---------|
| FR-01 | 게임 보드는 가로 10칸, 세로 20칸의 격자로 구성된다 |
| FR-02 | 보드 외곽(좌·우·하단)은 벽으로 취급하며 블록이 통과할 수 없다 |
| FR-03 | 보드 상단 초과 시 게임 오버로 처리한다 |

### 2.2 테트로미노 (블록)

| ID | 요구사항 |
|----|---------|
| FR-04 | 7가지 표준 테트로미노(I, O, T, S, Z, J, L)를 제공한다 |
| FR-05 | 각 테트로미노는 고유한 색상으로 구분된다 |
| FR-06 | 새 블록은 보드 상단 중앙에서 생성된다 |
| FR-07 | 다음에 등장할 블록(Next Piece)을 미리 보여준다 |
| FR-08 | 블록 생성 시 이미 공간이 없으면 게임 오버로 처리한다 |

### 2.3 블록 이동 및 조작

| ID | 요구사항 |
|----|---------|
| FR-09 | 블록은 일정 시간 간격(자동 낙하)으로 아래로 이동한다 |
| FR-10 | 블록이 바닥 또는 쌓인 블록에 닿으면 해당 위치에 고정된다 |
| FR-11 | 블록 고정 후 즉시 다음 블록이 생성된다 |
| FR-12 | 고스트 피스(현재 블록이 낙하할 최종 위치 미리보기)를 표시한다 |

### 2.4 키보드 입력

| ID | 키 | 동작 |
|----|-----|------|
| FR-13 | `←` (Left) | 블록을 왼쪽으로 1칸 이동 |
| FR-14 | `→` (Right) | 블록을 오른쪽으로 1칸 이동 |
| FR-15 | `↓` (Down) | 블록을 아래로 1칸 빠르게 이동 (소프트 드롭) |
| FR-16 | `↑` (Up) | 블록을 시계방향으로 90도 회전 |
| FR-17 | `Space` | 블록을 즉시 바닥까지 낙하 (하드 드롭) |
| FR-18 | `P` | 게임 일시정지 / 재개 토글 |
| FR-19 | `R` | 게임 재시작 |
| FR-20 | `Q` / `ESC` | 게임 종료 |

### 2.5 줄 삭제 및 점수

| ID | 요구사항 |
|----|---------|
| FR-21 | 가로 한 줄이 블록으로 꽉 차면 해당 줄을 삭제한다 |
| FR-22 | 줄 삭제 후 위에 있던 블록들은 삭제된 줄 수만큼 아래로 내려온다 |
| FR-23 | 한 번에 여러 줄(최대 4줄) 동시 삭제가 가능하다 |
| FR-24 | 줄 삭제 개수에 따라 점수를 부여한다 (아래 점수 표 참고) |
| FR-25 | 소프트 드롭 시 1칸당 1점을 추가로 부여한다 |
| FR-26 | 하드 드롭 시 낙하 거리(칸)의 2배 점수를 추가로 부여한다 |

**줄 삭제 점수표 (레벨 배수 적용)**

| 삭제 줄 수 | 명칭 | 기본 점수 |
|-----------|------|----------|
| 1줄 | Single | 100 × 레벨 |
| 2줄 | Double | 300 × 레벨 |
| 3줄 | Triple | 500 × 레벨 |
| 4줄 | Tetris | 800 × 레벨 |

### 2.6 레벨 시스템

| ID | 요구사항 |
|----|---------|
| FR-27 | 게임은 레벨 1부터 시작한다 |
| FR-28 | 10줄 삭제마다 레벨이 1 증가한다 |
| FR-29 | 레벨이 높아질수록 블록 자동 낙하 속도가 빨라진다 |
| FR-30 | 최대 레벨은 15로 제한한다 |

**레벨별 낙하 속도 (자동 낙하 간격)**

| 레벨 | 낙하 간격 (초) |
|------|--------------|
| 1 | 1.000 |
| 2 | 0.793 |
| 3 | 0.618 |
| 4 | 0.473 |
| 5 | 0.355 |
| 6 | 0.262 |
| 7 | 0.190 |
| 8 | 0.135 |
| 9 | 0.094 |
| 10+ | 0.083 |

### 2.7 게임 상태

| ID | 요구사항 |
|----|---------|
| FR-31 | 게임은 시작 화면 → 게임 진행 → 일시정지 → 게임 오버 순서로 상태가 전환된다 |
| FR-32 | 게임 오버 시 최종 점수, 레벨, 삭제 줄 수를 표시한다 |
| FR-33 | 게임 오버 후 재시작 또는 종료를 선택할 수 있다 |

## 3. 비기능 요구사항 (Non-Functional Requirements)

### 3.1 성능

| ID | 요구사항 |
|----|---------|
| NFR-01 | 키 입력 후 블록 이동까지의 응답 지연은 50ms 이하여야 한다 |
| NFR-02 | 게임 루프는 초당 최소 30 프레임으로 동작해야 한다 |

### 3.2 사용성

| ID | 요구사항 |
|----|---------|
| NFR-03 | 게임 화면에 현재 점수, 레벨, 삭제 줄 수, 다음 블록이 항상 표시되어야 한다 |
| NFR-04 | 블록과 배경은 색상으로 명확히 구분되어야 한다 |

### 3.3 실행 환경

| ID | 요구사항 |
|----|---------|
| NFR-05 | Python 3.10 이상 환경에서 실행되어야 한다 |
| NFR-06 | 렌더링 라이브러리는 `pygame`을 사용한다 (설치 필요: `pip install pygame`) |
| NFR-07 | Windows / macOS / Linux 환경에서 모두 실행 가능해야 한다 |

### 3.4 유지보수성

| ID | 요구사항 |
|----|---------|
| NFR-08 | 코드는 기능별로 모듈화되어 각 파일이 단일 책임을 가져야 한다 |
| NFR-09 | PEP 8 코딩 스타일을 준수한다 |

---

## 4. 제약사항

- 외부 라이브러리는 `pygame`만 허용한다 (표준 라이브러리 포함)
- 데이터 영속성(최고 점수 저장 등)은 1차 개발 범위에서 제외한다
- 멀티플레이어 기능은 구현하지 않는다
